# pypi 16Cent@999.0.1

**Source:** pypi_malregistry · **Source label:** malicious · **Released:** not found · **Assessment:** malicious (high) · **Analysis:** ai (claude-opus-5-5)

## Summary

The sdist's setup.py overrides the setuptools `install` command with `CustomInstall`. Its `run` method runs on a normal pip install from the sdist. It calls `install.run(self)` and then, with no environment check, sends the hostname, working directory and username to j0j0[.]xyz over three GET requests. One of those requests puts the hostname and username into the subdomain, so the data also leaks through DNS. It then uploads /etc/debconf.conf, /.dockerenv and /root/.wget-hsts to j0j0[.]xyz/files/. There are no gates. Each file read is unconditional, so a missing file only stops the uploads after it.

## Execution

- **cmdclass** `cmdclass[install] = CustomInstall`: runs setup.py; direct_script.
- **setup_py** `python setup.py (pip install from sdist)`: runs setup.py; direct_script.

## Gates

None.

## Requirements

- network: j0j0[.]xyz:443, 11cent[.]j0j0[.]xyz:80, *.*.j0j0[.]xyz:80 (recon GETs and file upload POSTs; the second GET goes to a hostname.username subdomain)
- other: requests module importable in the build environment (setup.py imports requests at top level but declares no build requirement; under pip build isolation the import fails before any payload runs)
- os: linux (the file reads use Linux paths)
- file_present: /etc/debconf.conf (read unconditionally and uploaded; absent on non-Debian systems, which aborts the remaining uploads)
- file_present: /.dockerenv (read unconditionally and uploaded; only present inside Docker containers)
- file_present: /root/.wget-hsts (read unconditionally and uploaded)
- privilege: root_or_admin (reading /root/.wget-hsts normally needs root)

## Behaviour

- Ungated: recon, exfil
- Gated: none

## Notes

- The file reads are not wrapped in try/except, so they count as requirements and not as gates. To see all three uploads, the scanner VM needs a Debian-like system running as root inside Docker (or with /.dockerenv present).
- `requests` is imported at the top of setup.py but is never declared as a build requirement. Under pip build isolation the import fails before any payload runs, so the build environment must already have requests installed.
- The version is 999.0.1 and the payload only does recon, which fits a dependency confusion probe. The family hint is left null because the domain is named after the author handle.
