# pypi 12Cent@999.0.0

**Source:** pypi_malregistry · **Source label:** malicious · **Released:** not found · **Assessment:** malicious (high) · **Analysis:** ai (claude-opus-5-5)

## Summary

The sdist overrides the setuptools `install` command (`cmdclass`), so `CustomInstall.run` executes on every pip install from source, after the normal install step. It reads the hostname and username, tries to create `/root/j0j0.poc`, lists `/`, `/root/`, `/home/` and `/root/.ssh/`, and POSTs the listings to `hxxps://j0j0[.]xyz/lists/<hostname>/<username>/`. There are no gates: each filesystem step sits in a try/except that only substitutes a placeholder string, and the exfil request runs unconditionally. Any Linux environment that can reach the endpoint and has `requests` installed sees the full behaviour; running as root makes the marker write and the /root listings succeed.

## Execution

- **cmdclass** `cmdclass[install] = CustomInstall`: runs setup.py; direct_script; errors hidden.
- **setup_py** `python setup.py (pip install from sdist)`: runs setup.py; direct_script.

## Gates

None.

## Requirements

- network: j0j0[.]xyz:443 (directory listings, hostname and username are POSTed here over HTTPS)
- other: Python package requests importable in the build environment (setup.py imports requests at top level without declaring it as a build requirement; without it setup.py fails before setup() runs)
- privilege: root_or_admin (the /root/j0j0.poc marker write and the /root and /root/.ssh listings only succeed as root; failures are swallowed and the POST still runs)
- os: linux (hard-coded POSIX paths (/root, /home); elsewhere the listings fall back to placeholder strings but the POST still runs)

## Behaviour

- Ungated: recon, write_file, exfil
- Gated: none

## Notes

- The prefilled candidate on `os.listdir('/root/.ssh/')` was dropped: the try/except only changes the data posted, not which behaviour runs.
- `requests` is imported at the top of setup.py but not declared as a build requirement, so in a clean isolated build environment the install fails before the payload runs.
- Version 999.0.0 and a marker file named `.poc` suggest a dependency-confusion style proof of concept, but nothing ties the name to an internal package, so attack_type is malicious_new_package.
