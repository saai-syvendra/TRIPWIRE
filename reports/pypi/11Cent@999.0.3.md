# pypi 11Cent@999.0.3

**Source:** pypi_malregistry · **Source label:** malicious · **Released:** not found · **Assessment:** malicious (high) · **Analysis:** ai (claude-opus-5-5)

## Summary

The sdist's setup.py registers a `cmdclass` install override (`CustomInstall.run`), which runs on a normal pip install from source after the stock install step. It tries to create `/root/j0j0.poc`, lists `/`, `/root/`, `/home/` and `/root/.ssh/`, and POSTs the listings to hxxps://j0j0[.]xyz/lists/. There are no gates: each try/except only replaces a failed listing with a placeholder string, and the POST runs either way. Any Linux environment that can reach that host triggers it. Running as root lets the marker write and the /root listings succeed.

## Execution

- **cmdclass** `cmdclass[install] = CustomInstall`: runs setup.py; direct_script; errors hidden.
- **setup_py** `python setup.py (pip install from sdist)`: runs setup.py; direct_script.

## Gates

None.

## Requirements

- network: j0j0[.]xyz:443 (directory listings are POSTed over HTTPS)
- other: python module requests importable in the build environment (setup.py imports requests at top level and fails before setup() runs without it)
- privilege: root_or_admin (the marker write to /root/j0j0.poc and the listings of /root/ and /root/.ssh/ only succeed as root; failures are swallowed)
- os: linux (hardcoded Unix paths /root/ and /home/)

## Behaviour

- Ungated: write_file, recon, exfil
- Gated: none

## Notes

I dropped the tool's candidate on the `/root/.ssh/` try/except because it is data collection: both outcomes feed the same request. `requests` must be importable or setup.py fails at import. Hostname, cwd and username are read but never used.
