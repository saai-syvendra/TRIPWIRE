# pypi 233_misc@0.0.3

**Source:** pypi_malregistry · **Source label:** malicious · **Released:** not found · **Assessment:** malicious (high) · **Analysis:** ai (claude-opus-5-5)

## Summary

The sdist's `setup.py` overrides the `install` command, so `execute.run` runs on a normal pip install. After the regular install step it writes a Python script, embedded as a string, to `remote-access.py`, moves it into the user's home folder (or `~/Documents` on Windows) and starts it with `python3` without waiting for it. That script keeps retrying a TCP connection to 120.76.194[.]25:20080 every 3 seconds, then serves a reverse shell over it (`cmd /K` on Windows, `/bin/bash -i` elsewhere). There is no install-time gate: the only OS check in `setup.py` just picks the drop folder, and the one in the dropped script just picks which shell to use.

## Execution

- **cmdclass** `cmdclass[install] = execute`: runs setup.py; direct_script, detached_child; errors hidden.
- **setup_py** `python setup.py (pip install from sdist)`: runs setup.py; direct_script.

## Gates

None.

## Requirements

- network: 120[.]76[.]194[.]25:20080 (dropped script connects here for the reverse shell and retries until it succeeds)
- installed_tool: python3 (dropped script is launched as python3 <home>/remote-access.py)
- installed_tool: bash (non-Windows arm of the dropped script runs /bin/bash -i)
- installed_tool: cmd (Windows arm of the dropped script runs cmd /K)

## Behaviour

- Ungated: write_file, spawn_process, reverse_shell
- Gated: none

## Notes

- The `sys.platform == "win32"` candidate at setup.py:89 was dropped as plumbing because both sides lead to the same write and launch.
- The OS branch inside the dropped script is inside a string literal and could not be anchored, so it is described in the notes rather than recorded as a gate.
- The GitHub URLs in `setup.py` are in comments and are not contacted.
- The Popen launch errors are swallowed. On Windows without a `python3` command the launch probably fails silently.
