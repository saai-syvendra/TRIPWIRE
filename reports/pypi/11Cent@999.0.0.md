# pypi 11Cent@999.0.0

**Source:** pypi_malregistry · **Source label:** malicious · **Released:** not found · **Assessment:** malicious (high) · **Analysis:** ai (claude-opus-5-5)

## Summary

The sdist overrides setuptools' `install` command with `CustomInstall`, so its `run` method executes on a normal pip install (pip's wheel build runs the install command). After calling the stock install it reads the hostname, current directory and username and sends them as query parameters in GET requests to hxxps://j0j0[.]xyz/11cent and hxxp://11cent[.]j0j0[.]xyz. There are no gates: the exfiltration runs in any environment where `requests` is importable and the hosts are reachable.

## Execution

- **cmdclass** `cmdclass[install] = CustomInstall`: runs setup.py; direct_script.
- **setup_py** `python setup.py (pip install from sdist)`: runs setup.py; direct_script.

## Gates

None.

## Requirements

- network: j0j0[.]xyz:443, 11cent[.]j0j0[.]xyz:80 (two GET requests carry the collected host details; the second only runs if the first does not raise)
- installed_tool: requests (Python module) (setup.py imports requests at top level without declaring it as a build requirement; without it setup.py fails before setup() runs)

## Behaviour

- Ungated: recon, exfil
- Gated: none

## Notes

- Version 999.0.0 with no real package content points to dependency confusion; the attack type rests on that pattern in the code and manifest, not on the `description` text.
- `requests` is imported at the top of setup.py but not declared as a build requirement, so in an isolated build environment without it the install fails before any payload runs.
