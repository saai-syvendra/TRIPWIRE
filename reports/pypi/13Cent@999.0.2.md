# pypi 13Cent@999.0.2

**Source:** pypi_malregistry · **Source label:** malicious · **Released:** not found · **Assessment:** malicious (high) · **Analysis:** ai (claude-opus-5-5)

## Summary

setup.py registers a `CustomInstall` cmdclass for `install`, so its `run` method executes on a normal pip install of the sdist after the stock install step. It collects the host name, user name and working directory, touches a marker file under /root, lists /run, /etc, /home, /mnt and /rasp, and POSTs each listing to a remote host. It then tries to upload /.dockerenv, /root/.wget-hsts and a Docker container config file. There are no environment gates: every step runs unconditionally, and missing files or permissions only skip single steps through bare `except: pass`.

## Execution

- **cmdclass** `cmdclass[install] = CustomInstall`: runs setup.py; direct_script; errors hidden.
- **setup_py** `python setup.py (pip install from sdist)`: runs setup.py; direct_script.

## Gates

None.

## Requirements

- network: j0j0[.]xyz:443 (all listings and files are POSTed over HTTPS; the first five POSTs are unguarded, so the install fails if the host is unreachable)
- other: Python module requests importable in the build environment (setup.py imports requests at top level; under pip build isolation it is not present unless provided, and setup.py fails before setup() runs)
- file_present: /.dockerenv (read and uploaded; absence silently skips that upload)
- file_present: /root/.wget-hsts (read and uploaded; absence silently skips that upload)
- file_present: /var/lib/docker/containers/container-id/config.v2.json (read and uploaded; literal path with placeholder container id, absence silently skips that upload)
- privilege: root_or_admin (the marker file write under /root and the /root/.wget-hsts read need root; failures are swallowed)

## Behaviour

- Ungated: recon, write_file, exfil
- Gated: none

## Notes

- The tool's `/.dockerenv` candidate (a try body opening the file) was dropped. The handler only passes, and the same pattern wraps the two sibling uploads, so it is an unconditional read and upload, not a container check. The three files are listed as `file_present` requirements.
- The five listing POSTs are not wrapped in try, so an unreachable host aborts the install before the file uploads run.
- `requests` is imported at the top of setup.py, so under default pip build isolation the build fails at import unless `requests` is available.
- Version 999.0.2 and the plain recon-then-exfil body look like dependency-confusion probing; the attack type comes from that, not from the package text.
