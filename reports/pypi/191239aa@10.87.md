# pypi 191239aa@10.87

**Source:** pypi_malregistry · **Source label:** malicious · **Released:** not found · **Assessment:** malicious (high) · **Analysis:** ai (claude-opus-5-5)

## Summary

The sdist builds through setuptools, so top-level code in `setup.py` runs at install. One gate (g1, `os.getlogin() != <author handle>`) excludes the author's own account and guards the whole payload. Behind it, on Windows, the code adds a HKCU `RunOnce` value pointing at `%TEMP%\temp-PipInstall.exe` and downloads an exe from a Dropbox share to that path with the system `curl.exe`, both with `CREATE_NO_WINDOW`. Any Windows login name other than the author's opens the gate; Windows, `TEMP`/`WINDIR`, curl.exe and network access to the share are requirements, not checks.

## Execution

- **setup_py** `python setup.py (pip install from sdist)`: runs setup.py; direct_script; errors hidden.

## Requirements

- os: win32 (Uses %TEMP%, %WINDIR%, reg.exe and subprocess.CREATE_NO_WINDOW, which only exist on Windows; elsewhere the payload raises.)
- other: env vars TEMP and WINDIR set (Read unconditionally with os.environ[...]; TEMP is outside the try and aborts setup.py when missing.)
- file_present: %WINDIR%\System32\curl.exe (The download runs the system curl.exe by absolute path (present on Windows 10 1803 and later).)
- installed_tool: reg (Persistence is set with reg add.)
- network: dl[.]dropboxusercontent[.]com:443 (Second-stage exe is downloaded from a Dropbox share.)

## Behaviour

- Ungated: none
- Gated: persistence, download, defense_evasion

## Notes

- `subprocess.call(...).wait()` raises AttributeError after the download, so the direct `os.system(malwPath)` launch never runs at install; the RunOnce entry starts the exe at next logon instead.
- On Linux the payload cannot run: `os.environ['TEMP']` (outside the try) raises KeyError, and `subprocess.CREATE_NO_WINDOW` does not exist there.
- The compared login name is the author handle (also in comments and metadata); redacted per rule 5. Family hint comes from the downloaded file name `esqueleDrp.exe`; the "EsqueleStealer" name appears only in a comment.
