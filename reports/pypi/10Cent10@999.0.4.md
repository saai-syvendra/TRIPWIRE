# pypi 10Cent10@999.0.4

**Source:** pypi_malregistry · **Source label:** malicious · **Released:** not found · **Assessment:** malicious (high) · **Analysis:** ai (claude-opus-5-5)

## Summary

`setup.py` overrides the setuptools `install` command with `CustomInstall`, which runs on a normal pip install of the sdist. After calling `install.run(self)` it opens a TCP socket to 104[.]248[.]19[.]57:3333, duplicates it onto fds 0, 1 and 2 and runs `pty.spawn("/bin/sh")`, a classic reverse shell. There are no gates: any environment that reaches the override runs the shell. It only needs a POSIX system, `/bin/sh`, the attacker host reachable and `requests` importable at build time.

## Execution

- **cmdclass** `cmdclass[install] = CustomInstall`: runs setup.py; direct_script.
- **setup_py** `python setup.py (pip install from sdist)`: runs setup.py; direct_script.

## Gates

None.

## Requirements

- network: 104[.]248[.]19[.]57:3333 (s.connect to the attacker host must succeed or an unhandled exception aborts the install before the shell is spawned)
- os: linux, darwin (top-level import pty (needs termios) and pty.spawn('/bin/sh') only work on POSIX systems)
- file_present: /bin/sh (shell spawned over the socket)
- other: python module requests importable in the build environment (unused top-level import requests in setup.py raises ImportError otherwise, so nothing runs)

## Behaviour

- Ungated: reverse_shell
- Gated: none

## Notes

- The unused top-level `import requests` means setup.py dies with ImportError in a build environment without requests (for example pip's isolated build env), so a sandbox may see nothing even though no check exists. Recorded as a requirement.
- The shell blocks the install in the foreground; it is not detached.
