# pypi 11Cent@999.0.1

**Source:** pypi_malregistry · **Source label:** malicious · **Released:** not found · **Assessment:** malicious (high) · **Analysis:** ai (claude-opus-5-5)

## Summary

The sdist's setup.py overrides the setuptools `install` command (`cmdclass={'install': CustomInstall}`), so the payload runs during a normal pip install from source after `install.run(self)`. With no gates at all, it collects hostname, working directory and username and sends them in three HTTP GETs to j0j0[.]xyz, one of them with hostname and username built into the subdomain. It then POSTs the contents of /etc/passwd and /etc/shadow to the same server. Any Linux host where the build environment has `requests` and outbound network access runs it, and root is needed for the /etc/shadow upload to succeed.

## Execution

- **cmdclass** `cmdclass[install] = CustomInstall`: runs setup.py; direct_script.
- **setup_py** `python setup.py (pip install from sdist)`: runs setup.py; direct_script.

## Gates

None.

## Requirements

- installed_tool: python package requests (imported at setup.py top level and used for every request; not declared as a build requirement)
- network: j0j0[.]xyz:443, 11cent[.]j0j0[.]xyz:80, <hostname>.<username>.j0j0[.]xyz:80 (beacons and file uploads; requests raises on connection failure and stops the remaining steps)
- os: linux (reads /etc/passwd and /etc/shadow by absolute path)
- file_present: /etc/passwd, /etc/shadow (opened unconditionally and posted to the server)
- privilege: root_or_admin (reading /etc/shadow needs root; otherwise PermissionError aborts after /etc/passwd is sent)

## Behaviour

- Ungated: recon, cred_read, exfil
- Gated: none

## Notes

- No conditions or candidates; the extractor found none, and reading the code confirms that.
- No error handling: on non-Linux hosts the open of /etc/passwd raises, and as a non-root user the open of /etc/shadow raises after /etc/passwd was already sent. Either way the install fails.
- `requests` is imported by setup.py but not declared as a build requirement, so in an isolated build env the build fails before the payload runs.
- Version 999.0.1 and the generic name suggest dependency confusion. The author field and domain are a handle, so no family hint is recorded.
