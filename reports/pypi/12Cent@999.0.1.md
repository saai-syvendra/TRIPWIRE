# pypi 12Cent@999.0.1

**Source:** pypi_malregistry · **Source label:** malicious · **Released:** not found · **Assessment:** malicious (high) · **Analysis:** ai (claude-opus-5-5)

## Summary

setup.py overrides the setuptools `install` command with `CustomInstall`, which runs on a normal pip install of the sdist. After the stock install it touches `/root/j0j0.poc` as a marker, lists `/run`, `/etc`, `/home`, `/mnt` and `/rasp`, and POSTs each listing to hxxps://j0j0[.]xyz with the hostname and username in the URL. It then uploads `/.dockerenv`, `/root/.wget-hsts` and `/run/docker.sock`. There are no environmental gates; the try/except fallbacks only change the posted text.

## Execution

- **cmdclass** `cmdclass[install] = CustomInstall`: runs setup.py; direct_script; errors hidden.
- **setup_py** `python setup.py (pip install from sdist)`: runs setup.py; direct_script.

## Gates

None.

## Requirements

- network: j0j0[.]xyz:443 (directory listings and files are POSTed over HTTPS to this host)
- other: python module requests importable in the build environment (imported at top level of setup.py; ImportError stops all install code)
- file_present: /.dockerenv (opened unconditionally before the file uploads; absence raises and aborts the remaining uploads)
- file_present: /root/.wget-hsts (opened unconditionally for upload)
- file_present: /run/docker.sock (opened unconditionally for upload (open() on a socket fails regardless))
- privilege: root_or_admin (reading /root/.wget-hsts and writing /root/j0j0.poc need root)
- os: linux (all probed paths are Linux or container paths)

## Behaviour

- Ungated: recon, write_file, exfil
- Gated: none

## Notes

- Attack type `dependency_confusion` is inferred from the 999.x version and the probe-and-report shape of the code; no internal package name it targets is known.
- The file uploads need the files to exist and root to read them; the first missing file raises and stops the rest. The docker socket cannot be read with open(), so the last upload never completes.
- `import requests` at the top of setup.py needs requests in the build environment, which pip's build isolation does not provide unless it is already there.
