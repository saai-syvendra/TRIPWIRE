# pypi 18923aa@4.96

**Source:** pypi_malregistry · **Source label:** malicious · **Released:** not found · **Assessment:** malicious (high) · **Analysis:** ai (claude-opus-5-5)

## Summary

The sdist builds with setuptools, so the top-level code of `setup.py` runs on pip install. One gate (g1) checks `os.getlogin()` against the author's own login name (redacted) and runs the payload for every other user. Behind it, inside a bare `try/except: pass`, the code adds a `HKCU\...\RunOnce` registry value pointing at `%TEMP%\temp-PipInstall.exe` and uses `%WINDIR%\System32\curl.exe` to download an exe from Dropbox to that path, both with hidden windows. Any Windows user whose login name is not the author's opens the gate; the payload needs `TEMP`, a working `os.getlogin()`, curl.exe and the Dropbox host to finish.

## Execution

- **setup_py** `python setup.py (pip install from sdist)`: runs setup.py; direct_script; errors hidden.

## Requirements

- os: win32 (uses WINDIR, TEMP, reg.exe, System32 curl.exe and subprocess.CREATE_NO_WINDOW (Windows only))
- other: env var TEMP set (os.environ['TEMP'] read outside the try; KeyError aborts setup.py otherwise)
- other: controlling terminal / login name available to os.getlogin() (os.getlogin() raises OSError without one, before the payload)
- file_present: C:\Windows\System32\curl.exe (download uses %WINDIR%\System32\curl.exe)
- installed_tool: reg (RunOnce persistence via reg add)
- network: dl[.]dropboxusercontent[.]com:443 (second-stage exe download)

## Behaviour

- Ungated: none
- Gated: persistence, download

## Notes

- The immediate run of the downloaded exe (line 17) is unreachable: line 16 calls `.wait()` on the int returned by `subprocess.call`, which raises AttributeError after the download, and the bare except swallows it. The exe still runs at next logon through the RunOnce value, recorded as persistence.
- The gate value is the author handle, redacted under rule 5. The recipe username "developer" is a guess (any other name works).
- Family hint EsqueleSquad rests on the `esqueleDrp.exe` filename in the download URL (code) and matches the publicly reported campaign; the header comment also names it.
- Dropbox share id redacted to `5mp5…`.
