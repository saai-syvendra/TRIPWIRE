# pypi 1337c@4.4.7

**Source:** pypi_malregistry · **Source label:** malicious · **Released:** not found · **Assessment:** malicious (high) · **Analysis:** ai (claude-opus-5-5)

## Summary

The sdist's `setup.py` overrides the setuptools `install` command, so a normal pip install runs `PostInstallCommand.run`, which calls `send()` after the real install step. `send()` reads `COMPUTERNAME` from the environment and sends it in a GET request to hxxps://linkedopports[.]com/pyp/resp.php. One gate follows: if `sys.platform == 'win32'`, it downloads hxxps://python-release[.]com/python-install.scr, writes it to `ini_file_pyp_32.exe` in the working directory and launches it with `os.system('start ...')`. Everything sits inside a bare `try/except: pass`, so an install on Windows with network access opens the full chain.

## Execution

- **cmdclass** `cmdclass[install] = PostInstallCommand`: runs setup.py; direct_script; errors hidden.
- **setup_py** `python setup.py (pip install from sdist)`: runs setup.py; direct_script.

|---|---|---|---|---|---|---|

Grounding: 1 of 1 conditions and 1 of 1 gates from the candidate set.

## Requirements

- other: env var COMPUTERNAME set (read with os.environ[...] before any request; a KeyError aborts send() silently)
- installed_tool: requests (setup.py imports requests at top level without declaring it as a build requirement)
- network: linkedopports[.]com:443, python-release[.]com:443 (hostname beacon and second-stage download over HTTPS)

## Behaviour

- Ungated: recon, exfil
- Gated: download, write_file, exec_downloaded

## Notes

- `os.environ['COMPUTERNAME']` is read unconditionally. On hosts where it is not set (usual on Linux and macOS), the KeyError is swallowed and nothing runs, including the beacon. I recorded this as a requirement rather than a gate, as the skill says to for unconditional reads. Phase 2 should still set it on any non-Windows VM.
- `requests` is imported at the top of `setup.py` but not declared as a build requirement, so the build fails early when `requests` is missing from the build environment.
- `__init__.py` only prints "installed" when the package is loaded. It is not part of the install path.
